## 핵심 문제점 TOP 5

### 1위. IA가 사용자 여정이 아니라 기능 이름으로 분절돼 있다

현재 오늘 / 기록 / 회고 / 이야기 거울 / 시각화는 내부 기능 목록으로는 이해되지만, 사용자는 "지금 무엇을 해야 하지?"라는 질문에 바로 답을 얻기 어렵다.

특히 회고, 이야기 거울, 시각화는 사실 모두 과거 기록을 다시 바라보는 경험이다. 이를 각각 최상위 페이지로 두면 서비스가 묵상 앱이라기보다 AI 도구 모음처럼 느껴진다.

**개선 방향 — 최상위 IA를 네 가지 역할로 재구성:**

- **오늘**: 지금 붙들어야 할 말씀과 결단
- **기록**: 묵상 작성과 과거 기록
- **돌아보기**: AI 회고, 이야기 거울, 시각화를 한 흐름으로 통합
- **보관함**: 저장한 말씀, 이미지, 회고, 결단

모바일 하단 네비게이션:

```
오늘 | 기록 | ＋ 새 묵상 | 돌아보기 | 보관함
```

회고 → 이야기 거울 → 시각화를 하나의 깊어지는 과정으로 만든다:

```
기록을 모아봄 → 반복되는 주제 발견 → 성경·고전 이야기와 연결 → 하나의 이미지로 기억 → 오늘의 결단으로 되돌림
```

### 2위. 모든 카드가 비슷한 크기와 목소리를 갖고 있다

오늘 페이지의 카드 밀도가 높다는 것은 카드 수 자체보다 모든 카드가 비슷한 강조도를 갖고 있다는 의미.

카드가 여섯 장인데 모두 둥근 모서리, 테두리, 제목, 본문, 버튼을 갖고 있으면 사용자의 눈에는 여섯 개의 할 일이 생긴다.

**개선 방향 — 각 화면을 세 단계 위계로 제한:**

1. **하나의 지배적 장면** (가장 큼)
2. **하나의 보조 행동** (중간 강조)
3. **조용한 기록 목록** (낮은 강조)

카드 사용 분리:
- 중요한 행동: 채워진 `ActionCard`
- 읽기 콘텐츠: 테두리가 거의 없는 `EditorialSection`
- 기록 목록: 행 형태의 `EntryRow`
- 상태 표시: 작은 `StatusStrip`

**모든 것을 카드로 감싸지 않는다. 여백이 곧 컴포넌트가 되게 해야 한다.**

### 3위. 묵상 작성이 빈 종이가 아니라 빈 양식으로 느껴진다

/entries/new에서 제목이 비어 있고 성구 선택이 불명확하면 사용자는 묵상 시작 전에 "제목을 무엇으로? 성구를 어디서? 무엇부터?"

**개선 방향:**

- 제목을 시작 필드에서 제거 → 저장 시 첫 문장 또는 AI 제안으로 생성
- 작성 화면은 3단계로 보이되 한 페이지에서 진행:
  1. 오늘 묵상한 말씀
  2. 마음에 남은 것
  3. 오늘 살아낼 한 가지

**권장 컴포넌트:**

```
MeditationComposer
├── ComposerHeader
├── ScripturePickerTrigger      ← 아이콘 버튼이 아닌 명확한 필드 형태
├── ScripturePreview
├── ReflectionTextarea
├── PromptDisclosure
├── CommitmentField
├── AutosaveStatus
└── ComposerActionBar
```

ScripturePickerTrigger 예시:

```
오늘 묵상한 말씀
[ 성경 구절을 선택하세요                         > ]
```

모바일에서 누르면 `ScripturePickerSheet`:
- 최근 읽은 말씀
- 성경명 검색
- 장·절 선택
- 직접 입력
- 여러 구절 추가

하단에는 항상 다음 액션이 보이게:

```
임시 저장됨                         [묵상 마치기]
```

### 4위. AI 결과가 "놀라운 콘텐츠"에서 끝나고 삶으로 되돌아오지 않는다

회고/이야기/시각화는 콘텐츠로서는 매력적이지만, 사용자가 다음 행동을 하지 않으면 한 번 보고 닫는 AI 전시관이 된다. AI가 어떤 기록을 근거로 해석했는지가 보이면 신뢰도 쌓인다.

**개선 방향 — 모든 AI 결과에 세 가지 층:**

1. **결과**: "최근 기록에서는 기다림과 통제 사이의 긴장이 반복되고 있어요."
2. **근거**: 기록 7개 · 성구 4개 · 열린 결단 2개를 바탕으로 작성. `EvidenceDrawer`에서 실제 연결 기록 확인.
3. **다음 행동**:
   - 오늘의 기도문으로 남기기
   - 결단으로 이어 쓰기
   - 관련 말씀 다시 읽기
   - 이미지로 기억하기

버튼 이름을 "더 보기" 대신 사용자가 얻게 되는 것으로:

```
나의 반복되는 주제 보기
왜 이 이야기와 닮았는지 보기
이 장면을 이미지로 기억하기
```

### 5위. 한국어 서비스인데 핵심 서체가 한글을 통제하지 못한다

Manrope와 Source Serif 4는 라틴/그리스/키릴 문자 중심. 한글 글리프가 없어 기기마다 다른 폴백.

**권장 조합:**

| 용도 | 현재 | 권장 |
|------|------|------|
| UI 레이블/네비 | Manrope (라틴) | **Pretendard** 또는 **Spoqa Han Sans Neo** |
| 본문/묵상 기록 | Source Serif 4 (라틴) | **Noto Serif KR** 또는 **Nanum Myeongjo** |
| 강조 헤드라인 | Manrope Bold | Pretendard Bold |
| 모노/코드 | — | **JetBrains Mono** 또는 **Spoqa Han Mono** |

## 6~8위 추가 문제점

### 6위. 모바일에서 터치 타겟이 작고 페이지 전환이 느리다

- 하단 네비게이션 아이콘 + 라벨 48px
- 카드 내부 버튼 최소 44px
- 페이지 전환: skeleton + 200ms fade-in (현재 없음)

### 7위. 색상 토큰이 충분히 활용되지 않는다

현재 gold, clay, leaf가 있지만 실제 카드/버튼에 거의 쓰이지 않음. 모든 것이 `white/95` + `border-line`.

개선:
- `gold` = 보조 CTA 배경
- `clay` = 기도/결단 하이라이트
- `leaf` = 링크/네비 활성
- `mist` = AI 결과 영역 배경

### 8위. 접근성 개선

- `h1` 1개 보장 (현재 일부 페이지에서 누락)
- `nav aria-label` 추가
- `:focus-visible` ring 점검
- `prefers-reduced-motion` 반영

## 2026 디자인 트렌드 반영

### 마이크로 인터랙션
- 카드 탭 시 `0.98` scale + 160ms border transition
- AI 결과 등장 시 `opacity + 8px translateY`, 240ms
- 좋아요/피드백: `0.95` scale bounce, 200ms

### 스크롤 기반 스토리텔링
- 오늘 페이지: 상단 "오늘 붙들 말씀"이 스크롤 시 자연스럽게 줄어들며 하단 기록으로 전환
- 회고 상세: sticky 섹션 네비게이션 (목차)

### 공백 활용
- 카드 간 24px → 섹션 간 48~64px
- 읽기 컨테이너 720px 고정, 양쪽 여백 충분
- AI 결과 영역에 `mist #f0f4f2` 배경으로 시각적 구분
