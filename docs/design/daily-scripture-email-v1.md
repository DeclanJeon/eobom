## 0. 목적

매일 하루 한 번, 사용자의 기록 상태에 맞는 성구와 그 성구의 배경 설명을 이메일로 보낸다.
기록이 흩어지고 다시 읽히지 않는 문제(PRD 2.1)를 "우리가 먼저 이어주는" 방식으로 보완한다.

핵심 규칙:
1. **기록이 있는 사용자** → AI가 최근 기록의 주제·감정을 파악해 그에 맞는 성구를 선택하고, 선택 이유와 배경을 함께 보낸다.
2. **기록이 없거나 적은 사용자** → 코퍼스에서 랜덤 성구를 선택하고 배경을 보낸다.
3. **하루 한 통, 한국시간 07:00 고정** — 매일 아침 같은 시각에 보낸다.
4. **신학적 안전성** — 배경은 역사·문맥 정보만. 설교·처방·판정 금지 (PRD 1.1, 1.7).
5. **이메일 채널 간 간섭 방지 (N1·N5)** — 일일 이메일이 이미 "기록하기" 안내를 포함하므로, **최근 24시간 내에 일일 이메일을 받은 사용자**에게는 미기록 리마인더(reminder_3d/7d)를 발송하지 않는다. 억제는 영구 폐지가 아니라 "24시간 내 두 통의 기록 압박 금지"다. 일일 이메일 채널이 켜져 있는 동안 리마인더 채널은 사실상 정지 상태가 되며, 이 운영 귀결은 §9에 명시한다.

## 2. 사용자 분기와 성구 선택

### 2.1 수신 대상과 분기 조건

**수신 대상 조건 (단일 정의):**
```
emailNotifications = true
AND claimedSeat != null
AND deletedAt = null
```

> **B1 해소:** `aiProcessingConsent`는 수신 대상 조건에 포함되지 않는다. 오직 **AI 맞춤 경로 진입 여부**를 가르는 분기 플래그로만 사용한다. 미동의자도 일일 이메일을 받되, AI 호출 없이 랜덤 경로만 탄다. (PRD 11.2: AI 외부 처리 별도 동의 원칙 — 랜덤 경로는 기록을 AI에 보내지 않으므로 동의 불필요.)

**분기:**
```
if aiProcessingConsent = true AND 최근 90일 기록 ≥ 3개:
    → AI 맞춤 경로 (2.3)
else:
    → 랜덤 경로 (2.2)   # 미동의자, 기록 부족자 모두 여기
```

**기록 3개 기준의 이유:** 1~2개 기록으로 주제를 추출하면 과적합이 된다. "시편 23편 한 번 읽은 사람"에게 시편만 계속 보내는 것을 막는다. 3개 미만은 랜덤 경로로 보내되, 이메일 하단에 "기록을 남기면 당신에게 맞는 성구를 골라 드립니다" 안내를 붙인다.

**프라이버시 방화벽:** `aiProcessingConsent = false`인 사용자의 기록 본문·성구·태그는 어떤 형태로도 AI 요청 페이로드에 포함되지 않는다. 이는 분기 조건에서 강제되며, 테스트로 단언한다 (C6).

### 2.2 랜덤 경로 (기록 없음 / 미동의자)

- 코퍼스 전체 장에서 가중 랜덤으로 장 선택 → 그 장에서 3~6절 연속 범위 선택
- **절 수 상한:** 장의 절 수가 3 미만이면(예: 시편 117편 = 2절) 그 장의 전체 절을 선택 (C6)
- **장 선택 가중치:** 절 수에 비례(긴 장이 더 자주)하되, 묵상 부적합 장은 제외:
  - 족보 장: 대상 1-9, 스 2, 느 7
  - 절 수 0인 장(코퍼스 결측) 자동 제외
- **14일 중복 제외:** 해당 사용자가 지난 14일 동안 받은 성구(EmailLog.meta 기반)와 장(chapter)이 겹치면 재선택. 같은 장을 매일 받지 않도록 한다.
- **배경 문구:** AI 없이 **정적 책 소개 데이터** 사용 (2.5절). AI 호출 비용 0.

### 2.3 AI 맞춤 경로 (기록 있음)

**입력 (사용자 기록에서 추출):**
- 최근 90일 기록의 성구: `scriptureBindings` 우선, 비어 있으면 `scriptureRefs`(표시 문자열)를 `parseBibleReferences`로 파싱해 보강 (C5)
- 기록 본문 발췌: **최신순 5개** 기록, 각 기록당 앞 300자 (C5)
- 태그·감정 필드

**AI 호출 1회로 성구 선택 + 배경 생성을 같이 한다** (비용 절감):

```json
{
  "scripture": { "code": "PSA", "chapter": 42, "startVerse": 1, "endVerse": 5 },
  "why": "선택 이유 1~2문장 (기록 주제와 연결)",
  "background": "본문 배경 3~4문장 (저자·상황·문학적 맥락)"
}
```

**배치 전용 타임아웃 (N3):** MiMo → DeepSeek 체인을 유지하되, 각 프로바이더당 단일 시도 30초·재시도 없음. 최악 사용자 1인당 ≤ 60초(두 프로바이더 연속 실패)로, 5명이면 ≤ 5분 — 10분 틱을 넘지 않는다 (B2).

**프롬프트 가드 (기존 review 가드 계승):**
- 하나님의 뜻 판정·믿음 평가·죄 확정·예언 금지
- 배경은 역사·문학 사실만. "당신은 ~해야 한다"는 처방 금지
- 이미 기록한 성구(scriptureRefs)는 선택 금지 → **새로운** 본문 제안
- **14일 내 이메일로 발송한 성구 목록을 선택 금지 목록으로 프롬프트에 주입** (B4)

**후처리 검증 (2단계):**
1. `getPassageFromRef`로 코퍼스 존재 검증 → 실패 시 랜덤 폴백
2. 14일 내 발송분(EmailLog.meta)과 장이 겹치면 랜덤 폴백 (B4)

### 2.4 폴백 체인과 멱등

```
AI 호출 → 성공 + 검증 통과 → AI 맞춤 발송
        → 실패/타임아웃/무효/14일 중복 → 랜덤 경로 + 책 배경 (로그 없음)

경로별 순서 (B2 — trySendWelcomeEmail 패턴, N2):
  AI 경로:  AI 호출 → 검증 → EmailLog 생성 → SMTP 발송
  랜덤 경로: 성구 선택 → EmailLog 생성 → SMTP 발송

멱등:
  1. EmailLog(daily_scripture, meta=성구ref slug)는 "선택·검증 완료 후, SMTP 발송 전"에 생성
     — ref는 AI 선택 이후에만 존재하므로 그 전에 생성할 수 없다 (N2)
  2. SMTP 발송 성공 → 로그 유지
  3. SMTP 발송 실패 → 로그 삭제 (다음 틱 재시도 가능)
  4. AI 실패 시점에는 아직 로그가 없음 → 삭제할 것 없음, 랜덤 폴백으로 처리
```

**프로세스 단일 인스턴스:** `flock`으로 스크립트 실행 잠금. 이전 실행이 끝나지 않았으면 새 틱은 즉시 종료.

**SMTP 서킷 브레이크 (C3):**
- 배치 시작 시 금일 발송 수 집계. Gmail 일 한도(500) 대비 잔여 < 대상 수면 초과분은 다음 날로 이월
- SMTP 인증/전송 실패가 3회 연속이면 해당 실행 중단 (한도 소진·차단 방지)
- 스팸함 노출(SPF/DKIM)은 §10 리스크에 deliverability 항목으로 관리

### 2.5 책 배경 콘텐츠 (B5 해소)

**범위: 66권 책 소개 (권별 1문단).** "장 컨텍스트"는 v1에서 제공하지 않는다.

- `data/bible/ko/book-intros.json` — 66개 항목: `{ "code": "PSA", "intro": "…" }`
- 각 소개는 책의 성격·저자 전통·핵심 주제를 2~3문장으로 서술. 설교적 결론 없이 사실·문맥만.
- 제작: 초안을 오프라인에서 작성하고, 공개 도메인/사실 기반 내용으로 제한. 66권은 구현 스코프 내 1회성 작업.
- 이메일 배경 문구 = 책 소개 + 선택된 성구 자체. AI 생성 배경은 AI 맞춤 경로에서만 사용.

> 1,171개 장별 배경은 데이터·검수 부담이 커서 v2 이후로 미루고, v1은 책 수준 배경으로 일관되게 제공한다.

## 3. 발송 시각

### 3.1 방식

**기준 타임존:** Asia/Seoul (KST). 14일 중복 제외, "오늘" 판단 전부 KST 기준.

**발송 시각:** 매일 **07:00 KST 1회**.

```
CRON_TZ=Asia/Seoul
0 7 * * * flock -n /tmp/eobom-email-daily.lock cd /home/declan/apps/eobom && /home/declan/.bun/bin/bun run scripts/email-daily.ts >> /home/declan/apps/eobom/logs/email-daily.log 2>&1
```

각 실행에서:
1. 오늘 이미 EmailLog(`daily_scripture`)가 있는 사용자 → skip (멱등)
2. 성구 선택 → EmailLog 생성 → SMTP 발송
3. SMTP 실패 시 로그 삭제 (다음날 재시도)

장점:
- 운영이 단순하다 (하루 1회)
- EmailLog로 같은 날 중복 발송 방지
- 아침 묵상 루틴과 맞는다

### 3.2 발송 창

- **매일 07:00 KST** (일요일 포함, 동일)

## 4. 이메일 템플릿

### 4.1 AI 맞춤 경로

```
제목: 오늘, {성구} — 기록이 가리킨 자리

안녕하세요, {이름}님.

최근 기록에서 {theme 한 단어}의 결이 자주 보였습니다.
그래서 오늘 이 본문을 권합니다.

{성구}
"{본문 3~6절 인용}"

— 배경 —
{AI 배경 3~4문장}

— 왜 이 본문인지 —
{why 1~2문장}

→ 이 본문으로 기록하기: {baseUrl}/entries/new?scripture={인코딩된 성구}

이 본문은 처방이 아니라 머무를 자리입니다.
```

**주의:** 이메일에 사용자 원문을 인용하지 않는다. "기록에서 ~한 결이 보였습니다" 수준의 주제어만. 원문은 채널 보안이 낮은 이메일에 싣지 않는다 (PRD 1.4 정신).

### 4.2 랜덤 경로 (기록 없음 / 미동의자)

```
제목: 오늘의 말씀 — {성구}

안녕하세요, {이름}님.

오늘 머무를 말씀입니다.

{성구}
"{본문 인용}"

— 배경 —
{책 소개 2~3문장}

→ 이 본문으로 기록하기: {baseUrl}/entries/new?scripture={성구}

기록을 남기기 시작하면, 당신의 기록에 맞는 본문을 골라 드립니다.
```

### 4.3 공통

- 하단 구독 해지 링크 (기존 `emailFooter`)
- 면책 문구: "이 이메일은 묵상 자료이며, 성경의 최종 해석을 대신하지 않습니다."

## 5. 데이터 모델

신규 테이블 없음. EmailLog에 `meta` 필드만 추가:

```prisma
model EmailLog {
  ...
  meta String?  // daily_scripture의 경우 "PSA-42-1-5" (slug 형식)
}
```

- `emailType = "daily_scripture"`
- **중복 방지:** 오늘(KST)에 `daily_scripture` 로그가 있으면 skip
- **14일 중복 제외:** 최근 14일 `daily_scripture` 로그의 `meta`에서 성구 ref 수집 → 장 기준 겹침 방지
- 기존 `email-batch.ts`/`email-digest.ts` 쿼리는 `emailType`/`userId`/`sentAt`만 필터하므로 `meta` 추가의 영향 없음

## 6. 비용 추정

| 경로 | AI 호출 | 대상 (14명 가정) |
|---|---|---|
| AI 맞춤 | 1회/사용자/일 (단일 시도 30초) | 기록 있는 ~5명 → 5회/일 |
| 랜덤 | 0 | ~9명 |

MiMo/DeepSeek 호출 5회/일 ≈ 월 150회. 무시 가능한 수준.
100명으로 확장 시: ~30회/일 ≈ 월 900회. 여유.

SMTP: 일 최대 발송 = 대상 수. Gmail 한도 500/일 대비 여유 (C3).

**`--to` 의미 (C1·C4 해소):**
- 실제 파이프라인을 타되 수신 주소만 오버라이드한 **실발송 스모크**다. `--dry-run`과 동시 사용 불가.
- **EmailLog(daily_scripture)를 기록하지 않는다** — 테스트 발송이 정식 중복 제외 풀을 오염시키지 않는다. 대신 콘솔에 스모크 결과만 출력.
- 주소에 매칭되는 사용자가 없으면 실패 종료(exit 1)한다.

**PRD 문서 개정 (C2):** PRD 9.8 알림 허용 목록에 "일일 묵상 성구 이메일" 항목을 추가한다.

## 9. 제외 대상 / 비목표

- 푸시 알림, 카카오톡 연동 (v1은 이메일만)
- 사용자별 발송 시각 커스터마이징 (v1은 07:00 KST 고정)
- 성구 난이도 조절, 번역본 선택 (코퍼스의 한국어 번역본 고정)
- 장별 배경 (v1은 책 수준 배경, 장별은 v2) (B5)
- 주간 요약과 통합 (별도 발송 유지 — 합치면 한 통이 너무 길어짐)

**운영 귀결 (N5):** 일일 이메일은 수신 대상 전원에게 매일 나가므로, 리마인더 억제 규칙(핵심 규칙 5)이 켜져 있는 동안 미기록 리마인더 채널은 사실상 정지 상태가 된다. 이것은 의도된 결과다 — 일일 이메일 자체가 "기록하기" 안내를 포함하므로 별도 리마인더가 중복 압박을 만들기 때문이다. 일일 이메일 채널을 중단하면 리마인더는 24시간 후 자동으로 재개된다.

## 10. 리스크

| 리스크 | 대응 |
|---|---|
| AI가 코퍼스에 없는 성구 생성 | 후처리 검증 + 랜덤 폴백 |

| 매일 발송 피로 / 리마인더 중복 | 최근 24시간 내 일일 이메일 수신자에게 리마인더 억제 (C2, N1). 구독 해지 원클릭 |
| aiProcessingConsent 없이 기록을 AI에 전송 | 분기 조건에서 강제 차단 + 프라이버시 방화벽 테스트 |
| 새벽 발송 실수 | cron 창을 7~19시(일요일 9시)로 제한 |
| 중복 발송 레이스 | create-before-send + flock 단일 인스턴스 (B2) |
| SMTP 한도 소진·계정 차단 | 서킷 브레이크 + 시작 시 잔여 한도 점검 (C3) |
| deliverability (스팸함) | SPF/DKIM 확인, 구독 해지 링크, 낮은 발송 빈도. 발송 후 수신함 도달 여부 수동 점검 (C3) |
| cron 타임존 | CRON_TZ=Asia/Seoul 고정. 매일 07:00 KST 1회 실행 |
